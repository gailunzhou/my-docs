    概述

    什么是IO

    输入

    输出

    哪些IO

    文件IO

    标准IO

    • stdin 标准输入
    • stdout 标准输出
    • stderr 用于输出错误信息

    以上三个本质都是一个文件

    网络IO

    IO模型分类

    1.阻塞IO

    应用程序在发起IO请求时会被IO操作阻塞，一直到IO操作完成才能继续进行下一步

    2.非阻塞IO

    应用程序发起IO请求后继续进行后续程序，不会等待IO操作结果，但是会轮询IO操作是否完成并获取结果

    3.IO多路复用

    应用程序通过一个系统调用来同时监视多个IO操作的状态，系统会在任何一个IO操作完成后返回结果（异步）

    4. 信号驱动IO模型

    程序将IO操作请求交给系统，系统会在IO操作完抽后发出一个信号，程序收到信号后会用专用的结果处理函数去处理操作结果

    5.异步IO

    和信号驱动IO模型类似，程序发起IO请求后会继续执行后面的操作，当系统完成IO请求后会发出一个通知，程序收到通知后会用回调函数来处理IO操作结果

    信号驱动IO模型和异步IO的区别

    • 信号驱动IO在收到信号后需要主动去调用IO相关函数将数据进行拷贝
    • 异步IO是等到内核将数据拷贝完成后才会通知，程序直接使用数据，无需进行拷贝
    • 信号驱动IO会在主动拷贝数据阶段发送阻塞
    • 异步IO全程无阻塞

    SOCKET套接字

    独立于具体协议的网络编程接口

    分类：

    • 流式嵌套字 TCP
    • 数据报嵌套字 UDP

    字节序

    小端序

    就是本地字节序：将低位数据放到内存的低位地址

    以 0x12345678为例就是0x78 56 34 12

    大端序

    就是网络字节序：将高位数据放到内存的低位地址

    以0x12345678为例就是0x12 34 56 78

    UDP网络编程

    基础版

    服务端

    1. 创建socket套接字（建立信箱）
    int serverFd = socket(AF_INET ,SOCK_DGARM ,0);
if(serverFd == -1)
{
    perror("服务端套接字创建失败\n");
    return -1;
}

    说明:

    socket套接字直接用socket()函数创建即可

    • 返回值：一个文件描述符，int类型，底层里对应一个复杂的数据结构

    • 参数1：网络协议是IPV4还是IPV6等 ，AF_INET是IPV4的意思

    • 参数2：套接字类型 SOCK_DGARM意思是数据报套接字
    • 参数3：传输协议，一般直接填0，系统会根据前面两个参数自动匹配协议（TCP还是UDP）
    2.创建地址（设置服务端的地址结构体）
    struct sockaddr_in serverAddr = {
  .sin_family = AF_INET,
  .sin_port = htons(8888),
  .sin_addr.s_addr = htonl(INADDR_ANY)
};

    说明：

    地址结构体sockaddr_in是转为IPV4协议创建的一个地址结构体，还有sockaddr结构体，是一个通用的地址结构体

    • 参数1：地址族，网络协议类型
    • 参数2：端口号，htons函数是将本地字节序host转换为网络字节序net
    • 参数3：允许接入的地址，INADDR_ANY是指允许任意IP都可以访问本地址
    3.绑定信箱和服务端地址
    int AddrLen = sizeof(serverAddr);
int bindRes = bind(serverFd ,(struct sockaddr*)&serverAddr ,AddrLen);
if(bindRes == -1)
{
    perror("绑定服务端套接字和地址失败\n");
    return -1;
}

    说明：

    绑定服务器套接字（文件描述符）和服务端地址需要使用bind函数

    • 返回值：绑定结果，int类型，如果是-1说明绑定失败
    • 参数1：服务端文件描述符
    • 参数2：sockaddr*类型的地址结构体的地址，由于前面创建的是sockaddr_in类型这里就需要强制类型转换
    • 参数3：地址结构体所占内存大小
    4.接收客户端信息
    //存储客户端数据的缓冲区
char buff[64];
//创建一个空的客户端地址结构体
struct sockaddr_in clientAddr;
//由于不止接收一次客户端信息，这里要用循环
while(1)
{
    //先将缓冲区清空
    bzero(buff ,64);
    //获取客户端地址所占内存大小
    AddrLen = sizeof(clientAddr);
    //接收数据
    int recvRes = recvfrom(serverFd ,buff ,64 ,0 ,(struct sockaddr*)&clientAddr ,&AddrLen);
    if(recvRes != -1)
    {
        //如果不为-1，说明已经成功连接了并且接收到数据了
        //获取客户端的端口
        int port = ntohs(clientAddr.sin_port);
        //获取客户端ip
        char *ip = inet_ntoa(clientAddr.sin_addr);
        //打印结果
        printf("ip:%s ,port:%d ,data: %s\n" ,ip ,port ,buff);
    }
}

    说明：

    前面创建了一个空的客户端地址结构体，后面连接了去获取端口和IP地址，是怎么获取的？

    当成功连接后，系统会自动将客户端信息填入到准备的这个空的客户端地址结构体

    bzero函数：属于strings.h头文件需要手动包含，作用是将指定字符串的指定长度清空

    接收客户端数据要使用recvfrom函数

    • 参数1：接收端文件描述符（服务端的文件描述符）
    • 参数2：存储接收数据的缓冲区
    • 参数3：一次最多接收多少字节数据
    • 参数4：标志位，一般都填0
    • 参数5：客户端地址结构体地址
    • 参数6：地址结构体所占内存大小

    获取客户端端口号：

    需要使用ntohs函数，因为客户端的数据是先发送到网络，再由网络发送到服务端，所以这里要使用网络字节序转本地字节序

    获取ip地址：

    需要使用inet_ntoa函数，还是和端口号同理，要把网络字节序转换为本地字节序

    客户端

    1.创建客户端套接字（准备信封）
    int clientFd = socket(AF_INET ,SOCK_DGRAM ,0);
if(clientFd == -1)
{
    perror("客户端套接字创建失败\n");
    return -1;
}

    方式和服务端相同

    2.指定服务端地址
    struct sockaddr_in serverAddr = {
  .sin_family = AF_INET,
  .sin_port = htons(8888),
  .sin_addr.s_addr = inet_addr("127.0.0.1")
};

    说明：

    和服务端不同的是，因为客户端要访问服务端，就需要指定服务端的IP，这里由于是本机作为服务端同时也作为客户端，同一个IP段，就直接指定为127.0.0.1

    3.准备发送的内容（准备信的内容）并发送
    //获取服务端地址所占内存大小
int AddrLen = sizeof(serverAddr);
char buff[64];
//因为可能不止发送一次数据，需要使用循环
while(1)
{
    //先清空当前缓冲区
    bzero(buff ,64);
    //提示输入
    printf("请输入要发送的数据：");
    scanf("%s" ,buff);
    //发送数据
    int sendRes = sendto(clientFd ,buff ,strlen(buff) ,0 ,(struct sockaddr*)&sockaddr_in ,&AddrLen);
    if(sendRes != -1)
    {
        printf("消息发送成功\n");
    }
}

    说明：

    和服务端大致相同，唯一区别是发送函数上

    要使用sendto函数进行发送，而且发送的字节数不能直接填缓冲区大小，为什么？

    因为具体发送的字节数不一定刚好是缓冲区大小，要使用strlen函数去获取具体的有效长度

    进阶版

    服务端

    要想使服务端还能在连接到客户端后还可以主动向客户端发送数据，需要使用线程，为什么？

    因为发送消息需要外部输入才有数据，这个过程是阻塞的，如果放到主线程中会一直等待外部输入，即使客户端那边发送数据过来也无法立即接收处理

    需要主动导入pthread.h头文件才可以使用线程

    具体步骤和基础版类似：

    1. 创建服务端套接字 int serverFd = socket(AF_INET ,SOCK_DFRAM ,0);
    2. 准备服务端地址 struct sockaddr_in serverAddr = {... ...};
    3. 绑定套接字和地址bind(serverFd ,(struct sockaddr*)&serverAddr ,AddrLen);
    4. 添加一步：创建子线程用于发送数据到客户端
    5. 循环接收客户端信息
    子线程相关步骤

    子线程的创建：

    pthread_t tid;
pthread_create(&tid ,NULL ,sendDataToClient ,NULL);

    说明：

    pthread_t是POSIX线程库中用于表示线程IO的类型，这里创建一个变量tid是后续创建的子线程的唯一标识符

    pthread_create函数用于创建子线程

    • 参数1：线程标识符的指针
    • 参数2：线程属性，填NULL表示默认属性
    • 参数3：线程的入口函数，也就是启动线程后要执行的函数
    • 参数4：传递给入口函数的参数，填NULL表示无参数

    子线程执行的函数

    void* sendDataToClient(void)
{
    //由于不止发送一次，这里要用循环
    while(1)
    {
        //清空缓冲区
        bzero(buff ,64);
        //提示
        printf("请输入要发送的数据：");
        scanf("%s" ,buff);
        //发送
        int sendRes = sendto(serverFd ,buff ,strlent(buff) ,0 ,(struct sockaddr*)&sockaddr_in ,AddrLen);
        if(sendRes != -1)
        {
            printf("发送数据成功\n");
        }   
    }
}

    客户端

    上面服务端会在连接后主动向客户端发送数据，因此客户端要接收，接收则应该单独放到一个子线程中进行，因为主线程中要从外部接收输入数据

    具体步骤和基础版类似：

    1. 创建套接字：int clientFd = socket(AF_INET ,SOCK_DGRAM ,0);
    2. 指定服务端地址：struct sockaddr_in serverAddr = {... ...};
    3. 添加的一步：创建子线程用于接收服务端消息
    4. 准备发送的信息并发送给服务端
    子线程相关步骤

    和服务端一致

    pthread_t tid;
pthread_create(&tid ,NULL ,receveFromServer ,NULL);

    具体不同就是子线程要执行的函数

    void *receveFromServer(void *data)
{
    //因为是在子线程中进行，且不止接收一次数据，所以要用循环
    while(1)
    {
        //先清空一次缓冲区
        bzero(recvBuff ,64);

        AddrLen = sizeof(serverAddr);

        int recvRes = recvfrom(clientFd ,recvBuff ,64 ,0 ,(struct sockaddr*)&serverAddr ,&AddrLen);

}

    最终版

    当有多个客户端时，客户端之间的通信是怎么完成的？

    每一个客户端的消息先发送到服务端，服务端再转发到目标客户端

    简单实现思路：

    服务端用一个数组去存储每一个连接过的客户端

    客户端发送的消息要限制格式，比如"num:xxxxxxx"其中num为-1时表示要在服务端进行注册，为其他时表示要给对应的客户端发送数据，例如"2:hello"的意思就是要给数组下标为2的客户端发送"hello"

    服务端

    具体实现步骤和进阶版相似：

    1. 创建服务端套接字：int serverFd = socket(AF_INET ,SOCK_DGARM ,0);
    2. 创建服务端地址结构体：struct sockaddr_in serverAddr = {... ...};
    3. 绑定套接字和地址结构体：int bindRes = bind(serverFd ,(struct sockaddr*)&serverAddr ,AddrLen);
    4. 创建子线程用于给客户端发送数据：pthread_t tid; pthread_create(&tid ,NULL ,... ...);
    5. 接收客户端的数据

    TCP网络编程

    TCP的三次握手和四次挥手

    三次握手

    • 第一次：客户端发送SYN请求连接服务端
    • 第二次：服务端收到请求，向客户端返回一个SYN-ACK包（意思是服务端确认收到了连接请求，向客户端请求连接）
    • 第三次：客户端收到请求，向服务端发送一个ACK包确认连接

    目的：防止已失效的连接请求报文再次发送到服务端，产生错误

    四次挥手

    • 第一次：客户端想要断开连接，发送一个FIN包给服务端（自己已发送完数据，请求断开连接）
    • 第二次：服务端收到客户端请求后返回一个ACK包（确认收到了FIN包，但此时只是单向断开）
    • 第三次：服务端向客户端发送FIN包向客户端请求断开连接
    • 第四次：客户端收到服务端的FIN包后会返回一个ACK包（确认收到了FIN包，此时才是双向断开）

    关于阻塞IO和非阻塞IO

    阻塞IO

    socket套接字所有的相关函数都是阻塞的，sendto，recvfrom

    • 优点：
    • 开发简单，容易入门，程序阻塞期间不会占用CPU资源
    • 缺点：
    • 如果有多个客户端连接，需要多开线程，比较占用空间

    非阻塞IO

    非阻塞模式下，一个线程中服务端可以和多个子线程进行IO操作

    • 优点：
    • 每次发起IO调用，在内核等待数据的过程中可以立即返回，主线程不会阻塞，实时性更好
    • 缺点：
    • 多个线程会不断轮询内核中是否已完成IO操作，比较占用CPU资源，效率不高

    fcntl(serverFd ,F_SETFL ,status);

    //因为不止和一个客户端会有建立连接，所以要用循环

    //创建一个空的客户端地址
    sockaddr_in clientAddr;

    while(1)
    {
        //和客户端建立连接
        //获取客户端地址所占内存
        AddrLen = sizeof(clientAddr);
        //建立连接 - accept 函数根据定义中 "When a connection arrives, open a new socket to communicate with it" 可知
        //当建立完连接后，会创建一个新的描述符，该描述符是专门用于与目标客户端通信的描述符，因此需要用一个描述符来接收返回值
        int clientFd = accept(serverFd ,(sockaddr *)&clientAddr ,&AddrLen);
        if(clientFd > 0)
        {
            //建立连接成功则打印信息
            int clientPort = ntohs(clientAddr.sin_port);
            char *ip = inet_ntoa(clientAddr.sin_addr);
            printf("客户端port:%d ip:%s 已连接\n" ,clientPort ,ip);

            //为了使读写操作时不会被阻塞，那么就需要将同于通信的文件描述符也修改为非阻塞
            status = fcntl(clientFd ,F_GETFL);
            status = status | O_NONBLOCK;
            fcntl(clientFd ,F_SETFL ,status);

            //建立连接完成后进行注册
            registerForClient(clientFd);
            printf("当前有%d个客户\n" ,counter);
        }

        //建立好连接后，因为不知道是哪个客户端有发送数据的请求，这里需要遍历
        for (size_t i = 0; i < counter; i++)
        {
            //清空缓冲区
            bzero(resBuff ,64);
            //接收数据
            int readRes = read(clientFds[i] ,resBuff ,64);
            if(readRes > 0)
            {
                printf("读取到来自客户端的数据：%s\n",resBuff);
                //回传给客户端
                write(clientFds[i] ,resBuff ,strlen(resBuff));
                //拆分数据
                char *token = strtok(resBuff ,".");
                //转换为int
                int index = atoi(token);
                //获取有效数据
                char *clientMsg = strtok(NULL ,".");
                //将数据转发给目标客户端
                write(clientFds[index] ,clientMsg ,strlen(clientMsg));
            }
            else if(readRes == 0)
            {
                printf("客户端断开连接\n");
                clientFds[i] = -1;
                counter --;
                printf("当前有%d个客户\n" ,counter);
                break;
            }
            else
            {
                continue;
            }
        }

    }

    return 0;
}

    IO多路复用

    实现方式：

    • 方式1：select
    • 方式2：poll
    • 方式3：epoll

    非阻塞形式2 - Select

    需要导入对应头文件sys/select.h

    要使用多路复用IO的形式

    客户端代码不变，主要是服务端要使用select进行重构

    基础步骤不变：

    1. 创建服务端文件描述符：int serverFd = socket(AF_INET ,SOCK_STREAM ,0);
    2. 创建服务端地址结构体：struct sockaddr_in serverAddr = {... ...};
    3. 绑定文件描述符和地址结构体：int bindRes = bind(serverFd ,(struct sockaddr*)&serverAddr ,&AddrLen);
    4. 监听客户端：int listenRes = listen(serverFd ,10);
    5. 使用select进行多路复用IO监听多个文件描述符
    6. 根据监听结果去执行对应操作

    select多路复用IO操作

    1.创建select集合
    //1.先定义一个select集合，用于存储要监听的文件描述符
fd_set setOfFd ,tmp;

    说明：

    • setOfFd：是存储要监听文件描述符的集合
    • tmp：是一个临时集合，为什么要有临时集合？因为select会修改传入的集合，这个临时集合就是用来保留原始集合的
    2.将存储文件描述符的集合中先都设置为0
    FD_ZERO(&setOfFd);
    3.将服务端的文件描述符添加到监听集合中
    FD_SET(serverFd ,&setOfFd);

    这里创建好集合时，一开始只有一个服务端的文件描述符，所以要将其添加进去

    4.设置select遍历的最大值

    为什么要设置一个最大值？

    因为select本质是一个线性表（链表），每次操作都需要遍历，需要手动设置一个遍历的最大值

    int maxFd = serverFd;//设置遍历最大的最大值为当前添加的服务端文件描述符
    5.设置select监听时间
    struct timeval timev = 
{
  .tv_sec = 3  
};

    为什么要设置一个监听时间？

    因为select监听某个文件描述符是否有事件变化时，需要给它设置一个超时时间，如果超过这个时间目标文件描述符还没有事件变化就返回0

    根据监听结果去执行对应操作

    //创建一个空的客户端地址结构体
struct sockaddr_in clientAddr;
//获取客户端地址结构体所占内存大小
int AddrLen = sizeof(clientAddr);
//创建一个接收客户端数据的缓冲区
char resBuff[64];
//循环，因为不会只接收一次
while(1)
{
    //由于select会修改原始的集合，这里先将原始集合拷贝
    tmp = setOfFd;
    //监听集合中的文件描述符是否有事件变化
    int retRes = select(maxFd + 1 ,&tmp ,NULL ,NULL ,&timev);
    if(retRes == -1)
    {
        perror("监听失败\n");
        return -1;
    }
    else if(retRes == 0)
    {
        //没有文件描述符有事件变化
        continue;
    }
    else
    {
        //文件描述符有事件变化
        //判断是哪些文件描述符有事件变化
        //服务端文件描述符有变化说明有客户端要进行连接
        if(FD_ISSET(serverFd ,&tmp) == 1)
        {
            //连接客户端
            int clientFd = accept(serverFd ,(struct sockaddr*)&clientAddr ,&AddrLen);
            if(clientFd > 0)
            {
                //有客户端连接并连接成功
                //获取客户端信息
                char *ip = inet_ntoa(clientFd.sin_addr);
                int port = ntohs(clientFd.sin_port);
                //打印信息
                printf("客户端已连接：ip:%s port:%d \n" ,ip ,port);
                //将获取的文件描述符添加到监听集合中
                FD_SET(clientFd ,&setOfFd);
                //判断是否需要更新遍历最大值
                maxFd = (clientFd > maxFd) ? (clientFd) : (maxFd);
            }
        }
        //如果是其他文件描述符有事件变化，则只能是客户端的通信文件描述符有事件变化，说明客户端发送数据过来了
        //遍历从服务端文件描述符后的每一个客户端文件描述符
        for(int i = serverFd+1 ;i < maxFd ; i++)
        {
            //判断是否有事件变化
            if(FD_ISSET(i ,&tmp) == 1)
            {
                //清空缓冲区
                bzero(resBuff ,64);
                //接收信息
                int recRes = read(i ,resBuff ,64);
                if(recRes > 0)
                {
                    //接收信息成功
                    printf("接收信息成功：%s \n" ,resBuff);
                    //回发给客户端
                    write(i ,resBuff ,strlen(resBuff));
                }
                else if(recRes == 0)
                {
                    printf("客户端断开连接\n");
                    break;
                }
                else if(recRes == -1)
                {
                    continue;
                }
            }
        }
    }
}
