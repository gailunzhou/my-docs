### 8  说一下C++面向对象的几个特征\****

C++ [面向对象编程](https://so.csdn.net/so/search?q=面向对象编程&spm=1001.2101.3001.7020) (OOP) 的三大特性包括：封装、继承和多态。

封装（Encapsulation）

封装是将数据（属性）和操作这些数据的函数（方法）组合在一个类（Class）中的过程。

封装的主要目的是隐藏类的内部实现细节，仅暴露必要的接口给外部。

通过封装，我们可以控制[类成员](https://so.csdn.net/so/search?q=类成员&spm=1001.2101.3001.7020)的访问级别（例如：public、protected 和 private），限制对类内部数据的直接访问，确保数据的完整性和安全性。

\#继承（Inheritance）

继承是一个类（派生类，Derived Class）从另一个类（基类，Base Class）那里获得其属性和方法的过程。

继承允许我们创建具有共享代码的类层次结构，减少重复代码，提高代码复用性和可维护性。

在 C++ 中，访问修饰符（如 public、protected、private）控制了派生类对基类成员的访问权限。

\#多态（Polymorphism）

多态是允许不同类的对象使用相同的接口名字，但具有不同实现的特性。

在 C++ 中，多态主要通过虚函数（Virtual Function）和抽象基类（Abstract Base Class）来实现。

虚函数允许在派生类中重写基类的方法，而抽象基类包含至少一个纯虚函数（Pure Virtual Function），不能被实例化，只能作为其他派生类的基类。

通过多态，我们可以编写更加通用、可扩展的代码，提高代码的灵活性。

总结：封装、继承和多态是面向对象编程的三大核心特性，能够帮助我们编写更加模块化、可重用和可维护的代码。

### 9 c++ 重载、重写、隐藏的区别

 重载（Overloading）:

重载是指相同作用域(比如命名空间或者同一个类)内拥有相同的方法名，但具有不同的参数类型和/或参数数量的方法。 重载允许根据所提供的参数不同来调用不同的函数。它主要在以下情况下使用：

· 方法具有相同的名称。

· 方法具有不同的参数类型或参数数量。

· 返回类型可以相同或不同。

· 同一作用域，比如都是一个类的成员函数，或者都是全局函数

 

重写是指在派生类中重新定义基类中的方法。

 

当派生类需要改变或扩展基类方法的功能时，就需要用到重写。

 

重写的条件包括：

方法具有相同的名称。

方法具有相同的参数类型和数量。

方法具有相同的返回类型。

重写的基类中被重写的函数必须有virtual修饰。

重写主要在继承关系的类之间发生。

隐藏是指派生类的函数屏蔽了与其同名的基类函数。注意只要同名函数，不管参数列表是否相同，基类函数都会被隐藏。

 

 

 重载和重写的区别：

范围区别：重写和被重写的函数在不同的类中，重载和被重载的函数在同一类中（同一作用域）。

参数区别：重写与被重写的函数参数列表一定相同，重载和被重载的函数参数列表一定不同。

virtual的区别：重写的基类必须要有virtual修饰，重载函数和被重载函数可以被virtual修饰，也可以没有。

隐藏和重写，重载的区别：

与重载范围不同：隐藏函数和被隐藏函数在不同类中。

参数的区别：隐藏函数和被隐藏函数参数列表可以相同，也可以不同，但函数名一定同；当参数不同时，无论基类中的函数是否被virtual修饰，基类函数都是被隐藏，而不是被重写。

### 13 C++ 中深拷贝和浅拷贝

拷贝（Shallow Copy）

​	浅拷贝是一种简单的拷贝方式，它仅复制对象的基本类型成员和指针成员的值，而不复制指针所指向的内存。

这可能导致两个对象共享相同的资源，从而引发潜在的问题，如内存泄漏、意外修改共享资源等。

一般来说编译器默认帮我们实现的拷贝构造函数就是一种浅拷贝。

POD(plain old data) 类型的数据就适合浅拷贝，对于 POD的理解可以看下这篇class和struct的区别(opens new window)

简单来说，浅拷贝也可以理解为直接按 bit 位复制，基本等价于 memcpy() 函数。

 ~~~c++
 class MyClass {
 private:
     int value;
     int* ptr;
 public:
     // 默认生成的浅拷贝构造函数等价于：
     MyClass(const MyClass& other) 
         : value(other.value), ptr(other.ptr) {}
 };
 ~~~



\#深拷贝（Deep Copy）

深拷贝不仅复制对象的基本类型成员和指针成员的值，还复制指针所指向的内存。

因此，两个对象不会共享相同的资源，避免了潜在问题。

深拷贝通常需要显式实现拷贝构造函数和赋值运算符重载。

```c++
class MyClass {
private:
    int* data;
    int size;
public:
    // 自定义深拷贝构造函数
    MyClass(const MyClass& other) 
        : size(other.size) {
        data = new int[size];
        for (int i = 0; i < size; ++i) {
            data[i] = other.data[i];
        }
    }
    
    // 析构函数
    ~MyClass() { delete[] data; }
};
```



### 14 运算符重载

​	在 C++ 中，运算符重载允许程序员为自定义类型重新定义运算符的行为，使其能够像内置类型一样自然地进行运算。这极大地增强了代码的可读性和可维护性。 

      ```c++
      class Complex {
      private:
          double real, imag;
      public:
          // 重载 + 运算符（成员函数）
          Complex operator+(const Complex& other) const {
              return Complex(real + other.real, imag + other.imag);
          }
          
          // 重载 += 运算符
          Complex& operator+=(const Complex& other) {
              real += other.real;
              imag += other.imag;
              return *this;  // 返回自身引用
          }
      };
      ```

### 15 虚函数和纯虚函数的联系和区别

+ ​联系:
  在 C++ 中，虚函数和纯虚函数是实现多态性的关键机制，它们都允许通过基类指针或引用来调用派生类的函数
  
+ 区别:
  + 定义方式：
    - 虚函数：virtual return_type func_name(param_list) {...}
    - 纯虚函数：virtual return_type func_name(paran_list) = 0;
  - 是否需要实现：
    - 虚函数：基类中可以有实现，也可以无实现
    - 纯虚函数：基类中无实现，但是可以有函数体
  - 对派生类的要求：
    - 虚函数：派生类中可以重写也可以不重写
    - 纯虚函数：如果派生类中不重写，则派生类也会变成一个抽象类，无法实例化
  - 类的性质：
    - 虚函数：包含虚函数的类可以实例化
    - 纯虚函数：包含纯虚函数的类无法实例化，只能作为基类被派生类继承
  - 设计意图：
    - 虚函数：提供一个可覆盖的默认方法，侧重于代码复用
    - 纯虚函数：强制派生类实现特定功能，用于定义接口和抽象概念

```c++
const int& cref = x; // 正确：常量左值引用，不可修改 x
int& bad_ref = 5;   // 错误：5 是右值（临时对象），不可绑定到非常量左值引用  不能通过引用修改值
```



右值引用的核心价值在于**识别临时对象并利用其即将被销毁的资源**，主要应用于：

- **移动语义**：避免深拷贝，提高资源转移效率。
- **完美转发**：在模板中保持参数的值类别。
- **标准库组件**：如智能指针、容器的插入操作等。



在 C++ 中，左值引用和右值引用是两种不同的引用类型，它们的核心区别在于所绑定的对象的 “属性”（左值还是右值）以及使用场景。理解它们需要先明确**左值**和**右值**的概念。

#### 一、左值（Lvalue）与右值（Rvalue）

- **左值**：可以取地址、有名字的对象（可以出现在赋值符号`=`的左边）。

  例如：变量、数组元素、返回左值引用的函数调用等。

  ```cpp
  int a = 10;  // a 是左值
  int arr[5];
  arr[0] = 20; // arr[0] 是左值
  ```

  

- **右值**：无法取地址、没有名字的临时对象（只能出现在赋值符号`=`的右边）。

  例如：字面量（`10`、`"hello"`）、表达式的临时结果（`a + b`）、函数返回的非引用临时对象等。

  ```cpp
  int b = a + 5;  // a + 5 的结果是右值
  string s = "abc";  // "abc" 是右值（临时字符串对象）
  ```

  

#### 二、左值引用（Lvalue Reference）

左值引用是最常用的引用类型，用`&`表示，**只能绑定到左值**。

它的本质是给已存在的左值起一个 “别名”，操作引用等价于操作原对象。

#### 特点：

1. 必须绑定到可修改的左值（除非用`const`修饰）。
2. `const`左值引用可以绑定到右值（临时对象），这是一个例外（为了方便传递临时值）。

#### 示例：

```cpp
int x = 10;
int& ref_x = x;  // 正确：左值引用绑定到左值 x
ref_x = 20;      // 等价于 x = 20，x 变为 20

// int& ref_temp = 100;  // 错误：左值引用不能直接绑定右值（100 是右值）

const int& ref_const = 100;  // 正确：const 左值引用可以绑定右值
// ref_const = 200;  // 错误：const 引用不可修改
```

#### 三、右值引用（Rvalue Reference）

右值引用是 C++11 引入的新特性，用`&&`表示，**专门用于绑定到右值**（临时对象）。

它的核心作用是**延长右值的生命周期**，并支持 “移动语义”（避免不必要的拷贝，提升性能）。

#### 特点：

1. 只能绑定到右值（临时对象、字面量等）。
2. 绑定后，右值的生命周期会被延长至与引用相同（原本临时对象会在表达式结束后销毁）。
3. 非`const`右值引用可以修改所绑定的右值（因为右值本身是临时的，修改不会影响其他对象）。

#### 示例：

```cpp
int&& ref_rv1 = 100;  // 正确：右值引用绑定到右值 100
ref_rv1 = 200;        // 正确：非 const 右值引用可以修改右值

int y = 20;
// int&& ref_rv2 = y;  // 错误：右值引用不能绑定到左值 y

// 绑定到表达式的临时结果（右值）
int&& ref_rv3 = (x + y);  // 正确，x + y 的结果是右值
```

#### 四、核心区别与应用场景

| 类型     | 符号 | 可绑定对象                  | 主要用途                                                     |
| -------- | ---- | --------------------------- | ------------------------------------------------------------ |
| 左值引用 | `&`  | 左值（`const`版可绑定右值） | 作为函数参数（避免拷贝）、返回对象别名等。                   |
| 右值引用 | `&&` | 右值                        | 实现移动语义（移动构造函数、移动赋值运算符）、完美转发，提升性能。 |

##### 1. 移动语义（右值引用的核心价值）

当对象包含堆内存（如`std::string`、`std::vector`）时，拷贝操作（如拷贝构造）需要复制堆内存，代价较高。而**移动操作**可以 “窃取” 右值对象的资源（如堆指针），避免拷贝，大幅提升性能。

示例（简化的移动构造）：

```cpp
class MyString {
private:
    char* data;
public:
    // 移动构造函数（参数为右值引用）
    MyString(MyString&& other) noexcept {
        data = other.data;  // 直接窃取资源
        other.data = nullptr;  // 原对象放弃资源所有权
    }
};

MyString get_string() {
    return MyString("hello");  // 返回临时对象（右值）
}

int main() {
    MyString s1 = get_string();  // 调用移动构造，而非拷贝构造
    return 0;
}
```

##### 2. 完美转发（右值引用的另一重要应用）

通过右值引用和模板，可以实现函数参数的 “完美转发”—— 保持参数的左值 / 右值属性不变，传递给内部函数。

示例：

```cpp
template <typename T>
void forward_func(T&& arg) {  // 万能引用（可接收左值或右值）
    other_func(std::forward<T>(arg));  // 完美转发，保持 arg 的原始属性
}
```

#### 五、总结

- 左值引用（`&`）绑定左值，主要用于别名和避免拷贝。
- 右值引用（`&&`）绑定右值，核心是支持移动语义和完美转发，解决临时对象的性能问题。
- `const`左值引用可以绑定右值，但无法修改；右值引用可以修改所绑定的右值，且能延长其生命周期。

理解左值引用和右值引用是掌握现代 C++（如移动语义、智能指针）的基础。

### 6. 创建进程（补充区别）

- `fork()`：复制父进程地址空间（写时复制），子进程与父进程独立运行，返回值：父进程得子进程 PID，子进程得 0；
- `vfork()`：子进程共享父进程地址空间，且父进程会阻塞直到子进程调用`exec`或`exit`（避免竞争，效率更高，但需注意内存共享问题）；
- 实际开发中常用`fork()+execvp()`组合：`fork`创建子进程后，`execvp`加载新程序替换子进程（如启动 QT 程序或更新进程）。

### 7. 同主机进程间通信（补充特点）

- **信号**：异步通知机制（如`SIGINT`中断、`SIGUSR1`自定义信号），适合简单事件触发，携带信息少；
- System V IPC
  - 消息队列：按类型发送 / 接收消息（`msgget`/`msgsnd`/`msgrcv`），适合数据量小的异步通信；
  - 共享内存：进程直接映射同一块物理内存（`shmget`/`shmat`），速度最快，需配合同步机制（如信号量）；
  - 信号量：用于互斥与同步（`semget`/`semop`），通过 P/V 操作控制资源访问。

### 10. 线程间通信（补充优势）

- 线程共享进程地址空间，因此**全局变量**是最直接的通信方式（需配合同步机制）；

### 11. 线程安全（补充适用场景）

- **互斥锁（pthread_mutex_t）**：最常用，确保同一时间只有一个线程执行临界区（如修改全局变量）；
- **读写锁（pthread_rwlock_t）**：读多写少场景优化，允许多个读线程同时访问，写线程独占；
- **信号量（sem_t）**：用于控制线程并发数（如限制 5 个线程同时访问资源）；
- **条件变量（pthread_cond_t）**：线程间同步（如等待某个条件满足，如队列非空）。

### 12. 线程死锁（补充规避方法）

死锁成因：循环等待、互斥、不可剥夺、持有并等待。

规避措施：

- 按**固定顺序加锁**（如所有线程都先锁 A 再锁 B）；
- 加锁时设置超时（`pthread_mutex_timedlock`），超时后释放已持有的锁；
- 定期检测死锁（如通过`pstack`查看线程调用栈，分析锁持有情况）。

### 13. 生产者 - 消费者模式实现（补充流程）

基于**队列 + 互斥锁 + 条件变量**：

- 队列：存储数据（如环形缓冲区）；

- 互斥锁：保护队列操作（入队 / 出队）的原子性；

- 条件变量：

  - 生产者：队列满时等待（`pthread_cond_wait`），生产后通知消费者（`pthread_cond_signal`）；

  - 消费者：队列空时等待，消费后通知生产者。

### 14. Linux 网络 IO 模型（补充适用场景）

- **阻塞 IO**：简单但效率低，适合连接数少的场景（如单机调试），配合线程池可处理多连接（每个连接一个线程）；

- **非阻塞 IO**：通过`fcntl`设置`O_NONBLOCK`，轮询检查 IO 状态，避免阻塞但消耗 CPU；

- IO 多路复用

  ：

  - `select`：监听有限个文件描述符（默认 1024），轮询效率低；
  - `poll`：无文件描述符数量限制，仍需轮询；
  - `epoll`：Linux 特有，事件驱动（回调机制），支持边沿触发（ET）和水平触发（LT），适合高并发（如服务器处理 thousands 级连接）。

### 16. HTTP 与 TCP 的联系和区别

- **联系**：HTTP 基于 TCP 传输层协议，建立连接需先完成 TCP 三次握手，数据传输依赖 TCP 的可靠性。

- 区别

  ：

  | 层面     | TCP                   | HTTP                                          |
  | -------- | --------------------- | --------------------------------------------- |
  | 协议层级 | 传输层                | 应用层                                        |
  | 功能     | 提供可靠字节流传输    | 定义请求 / 响应格式（如 URL、Method、Header） |
  | 数据处理 | 需手动处理粘包 / 拆包 | 自带消息边界（如 Content-Length）             |
  | 状态     | 有状态（连接保持）    | 无状态（需 Cookie/Session 维持会话）          |

### 17. 私有网络协议定义（补充 TLV 细节）

基于 TCP 的私有协议需解决**粘包 / 拆包**和**数据结构**问题，常用 TLV 格式：

- **Type（类型）**：1-2 字节，标识数据用途（如 0x01 表示心跳，0x02 表示业务数据）；

- **Length（长度）**：2-4 字节，标识 Value 字段的字节数（解决粘包）；

- Value（值）

  ：实际数据（如 JSON、二进制结构体，需定义字段含义）。

  

  扩展：可增加校验位（如 CRC）确保完整性，或加密 Value 字段（如 AES）保证安全性。

### 18. 网络四层模型及协议

- **数据链路层**：负责物理层数据帧传输，协议如 Ethernet（以太网）、PPP（点对点协议）；
- **网络层**：路由与寻址，核心协议 IP（IPv4/IPv6），辅助协议 ICMP（网络控制，如 ping）、ARP（地址解析）；
- **传输层**：端到端数据传输，TCP（可靠、面向连接）、UDP（不可靠、无连接，如视频流）；
- **应用层**：定义业务交互规则，如 HTTP（网页）、SSH（远程登录）、HTTPS（加密 HTTP）、MQTT（物联网通信）。

### 19. TCP 三次握手

目的：建立可靠连接，确保双方收发能力正常。

- **第一次**：客户端→服务器，发送 SYN（同步序列编号），客户端进入 SYN_SENT 状态；
- **第二次**：服务器→客户端，回复 SYN+ACK（确认客户端 SYN），服务器进入 SYN_RCVD 状态；
- **第三次**：客户端→服务器，发送 ACK（确认服务器 SYN），双方进入 ESTABLISHED 状态，开始传输数据。

### 20. 保证数据传输安全与完整性

- **完整性**：通过校验和（如 CRC32）、哈希算法（如 SHA256）检测数据是否被篡改；

- 安全性

  ：

  - 加密：对称加密（AES）加密数据内容，非对称加密（RSA）加密对称密钥；
  - 签名与验签：发送方用私钥签名数据哈希，接收方用公钥验签（确保数据来源合法且未篡改）；
  - 场景：HTTPS 通过 TLS 协议实现加密与验签，嵌入式中常用 OpenSSL 库实现。

### 21. 常用 C 库（补充用途）

- **C 标准库**：基础功能（`stdio.h`输入输出、`stdlib.h`内存管理、`pthread.h`线程）；
- **glib**：GNOME 基础库，提供数据结构（链表、哈希表）、事件循环、线程池等；

#### ***\*6 详解Qt中的内存管理机制\****   对象树

**\1. 所有继承自QOBJECT类的类，如果在new的时候指定了父亲，那么它的清理时在父亲被delete的时候delete的，所以如果一个程序中，所有的QOBJECT类都指定了父亲，那么他们是会一级级的在最上面的父亲清理时被清理，而不用自己清理；**

\2. 程序通常最上层会有一个根的QOBJECT，就是放在setCentralWidget（）中的那个QOBJECT，这个QOBJECT在 new的时候不必指定它的父亲，因为这个语句将设定它的父亲为总的QAPPLICATION，当整个QAPPLICATION没有时它就自动清理，所以也无需清理。9这里QT4和QT3有不同，QT3中用的是setmainwidget函数，但是这个函数不作为里面QOBJECT的父亲，所以QT3中这个顶层的QOBJECT要自行销毁）。

\3. 这是有人可能会问那如果我自行delete掉这些QT接管负责销毁的指针了会出现什么情况呢，如果时这样的话，正常情况下QT的拥有这个对象的那个父亲会知道这件事情，它会直到它的儿子被你直接DELETE了，这样它会将这个儿子移出它的列表，并且重新构建显示内容，但是直接这样做时有风险的！也就是要说的下一条

\4. 当一个QOBJECT正在接受事件队列时如果中途被你DELETE掉了，就是出现问题了，所以QT中建议大家不要直接DELETE掉一个 QOBJECT，如果一定要这样做，要使用QOBJECT的deleteLater()函数，它会让所有事件都发送完一切处理好后马上清除这片内存，而且就算调用多次的deletelater也不会有问题。

\5. QT不建议在一个QOBJECT 的父亲的范围之外持有对这个QOBJECT的指针，因为如果这样外面的指针很可能不会察觉这个QOBJECT被释放，会出现错误，如果一定要这样，就要记住你在哪这样做了，然后抓住那个被你违规使用的QOBJECT的destroyed（）信号，当它没有时赶快置零你的外部指针。当然我认为这样做是及其麻烦也不符合高效率编程规范的，所以如果要这样在外部持有QOBJECT的指针，建议使用引用或者用智能指针，如QT就提供了智能指针针对这些情况，见***一条。

QT中的智能指针封装为QPointer类，所有QOBJECT的子类都可以用这个智能指针来包装，很多用法与普通指针一样，可以详见QT assistant 通过调查这个QT的内存管理功能，发现了很多东西，现在觉得虽然这个QT弄的有点小复杂，但是使用起来还是很方便的，***要说的是某些内存泄露的检测工具会认为QT的程序因为这种方式存在内存泄露，发现时大可不必理会。

#### 1. **如何实现图像滤波？常用的滤波器有哪些？**

- **滤波原理**：通过卷积核在图像上滑动，对每个像素及其邻域进行计算，实现平滑、锐化等效果。

- 常用滤波器

  ：

  - **均值滤波**：用邻域平均像素值替代当前像素，易模糊边缘。
  - **高斯滤波**：根据高斯函数分配邻域权重，保边效果更好。
  - **中值滤波**：用邻域像素的中值替代当前像素，适合去除椒盐噪声。
  - **双边滤波**：同时考虑空间距离和像素值差异，保留边缘的同时平滑区域内部。

#### 2. **简述 Canny 边缘检测的步骤**

1. **高斯平滑**：消除噪声。
2. **计算梯度**：用 Sobel 算子计算图像梯度幅值和方向。
3. **非极大值抑制**：保留局部梯度最大值，细化边缘。
4. **双阈值检测**：用高低两个阈值连接边缘（高于高阈值为强边缘，介于两者之间且连接到强边缘的为弱边缘）。

#### 3. **如何实现图像二值化？自适应阈值和固定阈值的区别是什么？**

- **固定阈值**：使用`cv2.threshold()`，全局统一阈值（如大于 127 设为 255，否则为 0）。
- **自适应阈值**：使用`cv2.adaptiveThreshold()`，根据像素邻域计算局部阈值，适合光照不均场景。

## 五 嵌入式物联网

###  嵌入式开发经验

做过 STM32 和 ESP32 单片机开发，涉及外设驱动、RTOS 任务管理、传感器数据采集与通信协议应用（如 I²C、SPI、UART），以及低功耗优化和 OTA 升级等功能开发。

### 2. 驱动开发经验

专注于单片机外设驱动开发，包括 GPIO 配置、UART/SPI/I²C 等通信协议驱动、传感器（温湿度、光照等）驱动，以及继电器、电机等执行器的控制驱动。

### 3. 常见外设协议（核心分类与特点）

- 串行协议

  ：

  - UART：异步通信，依赖波特率，用于调试、传感器数据传输；
  - SPI：同步全双工，高速率，用于连接 Flash、ADC 等；
  - I²C：同步半双工，双线制，支持多设备，用于 EEPROM、低速率传感器；
  - CAN：工业总线，高可靠性，多主通信，用于汽车 / 工业控制。

- 并行协议

  ：

  - FSMC：并行接口，扩展存储或驱动 LCD；
  - GPIO：基础输入输出，控制 LED、按键，可模拟软件协议。

- 其他

  ：

  - ADC/DAC：模拟信号转换，用于传感器数据采集和波形生成；
  - PWM：通过占空比控制电机、LED 亮度。

### 4. GPIO（通用输入输出）

- **输入模式**：浮空（易受干扰）、上拉（默认高电平）、下拉（默认低电平）、模拟输入（接 ADC）。
- **输出模式**：推挽（高低电平驱动能力强）、开漏（需外部上拉，支持线与逻辑）、复用模式（外设控制引脚）。
- **扩展功能**：外部中断触发（如按键检测）、输出速度配置（平衡信号质量与功耗）。

### 5. I²C 时序（核心流程）

- **起始条件（S）**：SCL 高电平时，SDA 由高变低。
- **数据传输**：SCL 高电平时 SDA 稳定（数据有效），8 位数据后接应答位（ACK/NACK）。
- **停止条件（P）**：SCL 高电平时，SDA 由低变高。
- **通信流程**：起始→发送从机地址 + 读写位→应答→数据传输→停止 / 重复起始。

### 6. FreeRTOS 使用经验

- 轻量级开源 RTOS，适合 STM32/ESP32 等 MCU，支持多任务、同步机制和低功耗模式。
- 核心优势：可裁剪、资源占用少（ROM≈4KB，RAM≈1KB）、调度灵活。

### 7. FreeRTOS 任务调度

- **抢占式调度**：高优先级任务可打断低优先级任务，保证实时性。
- **时间片轮询**：同优先级任务按时间片（由系统滴答定时）轮流执行。
- 混合模式：高优先级抢占，同优先级轮询，兼顾实时性与公平性。

### 8. FreeRTOS 任务间通信

- **消息队列**：传递数据缓冲区，支持异步通信（最常用，如传感器数据传递）。
- **信号量**：控制资源访问（二进制信号量）或计数（计数信号量）。
- **互斥量**：解决资源竞争，支持优先级继承（避免优先级反转）。
- **事件组**：多事件触发（如多个传感器状态满足时执行动作）。
- **任务通知**：轻量级替代信号量 / 队列，直接向任务发送事件。

### 9. FreeRTOS 内存管理

- **静态管理**：用户手动分配 / 释放内存（如任务栈、队列缓冲区），无碎片。

- 动态管理

  ：系统自动分配，提供 5 种策略（heap_1~heap_5）：

  - heap_4：支持最佳适配和空闲块合并，抗碎片能力强；
  - heap_5：支持多内存区域，适合外设扩展存储。

### 10. UART（通用异步收发器）

- 异步串行通信，无需时钟线，通过波特率同步。
- 关键参数：波特率（9600、115200bps）、数据位、停止位、校验位。
- 应用：串口调试、传感器通信、与 PC 交互（需 USB 转 UART 芯片）。

### 11. SPI 与串口屏

- **SPI 特点**：同步全双工，4 线（SCLK、MOSI、MISO、SS），高速率，支持多从设备。
- 未做过串口屏，使用过 I²C 接口屏幕（如 OLED 屏）。

### 12. RS232 与 RS485 的区别

- **RS232**：点对点，单端传输，距离短（≤15m），速率低（≤20kbps），适合近距离设备（如 PC 与 MCU）。
- **RS485**：差分传输，支持多节点（≤32 个），距离长（≤1200m），速率高（≤10Mbps），适合工业总线（如设备联网）。

### 13. CAN 总线

未实际使用，了解其为工业现场总线，高可靠性，支持多主通信和错误检测，广泛用于汽车电子和工业自动化。

### 14. MODBUS

未提及具体使用经验，通常用于工业设备通信，基于串口（RTU 模式）或 TCP/IP（TCP 模式），支持主从问答式数据传输。

### 15. LoRa

无线通信技术，相比 WiFi / 蓝牙传输距离更远（公里级），低功耗，适合物联网远距离低速率场景（如户外传感器数据上传）。

### 16. EEPROM 用途

用于存储掉电不丢失的小容量数据，如设备配置信息（阈值、配网参数）、设备 SN 等。

### 17. 蓝牙用途

- 短距离无线通信，支持主模式、从模式、主从一体模式。
- 应用：设备配置信息传输（如手机 APP 配置设备参数）、近距离数据交互。

### 18. WiFi 工作模式

- **STA 模式**：设备连接外部 WiFi 热点（如连接路由器上网）。
- **AP 模式**：设备自身作为热点，供其他设备连接（如本地配置设备）。
- **STA+AP 模式**：同时支持连接外部热点和作为热点，兼顾联网与本地配置。

### 19. ARM 架构特点

- 精简指令集（RISC），指令少且固定长度，执行效率高。
- 低功耗设计，适合移动端和物联网设备（如 Cortex-M 系列 MCU）。
- 模块化可扩展，支持异构计算（CPU+GPU+NPU），生态丰富（支持 Linux、RTOS）。

### 20. FreeRTOS 特点

- 开源免费，轻量级（资源占用少），可裁剪（通过 FreeRTOSConfig.h 配置）。
- 支持多任务抢占式调度、丰富的同步机制（信号量、队列等）、低功耗模式（Tickless）。

### 21. FreeRTOS 任务状态及转换

- **状态**：就绪（等待调度）、运行（占用 CPU）、阻塞（等待事件）、挂起（主动暂停）、终止（任务结束）。

- 转换

  ：

  - 就绪→运行：调度器选择最高优先级任务；
  - 运行→阻塞：任务调用延时或等待资源；
  - 阻塞→就绪：等待的事件触发（如延时结束、资源可用）；
  - 挂起→就绪：调用 vTaskResume () 恢复。

### 22. FreeRTOS 默认调度方式

默认采用**抢占式调度 + 时间片轮询**：高优先级任务抢占执行，同优先级任务按时间片轮流执行。

### 23. FreeRTOS 任务调度流程

以优先级为核心，通过系统滴答中断（SysTick）触发调度器，选择最高优先级就绪任务执行，若有更高优先级任务就绪则立即切换（抢占），同优先级任务按时间片轮转。

### 24. FreeRTOS 中断机制

- 中断发生时，硬件自动保存部分现场（PC、PSR 等），软件通过中断服务程序（ISR）保存剩余上下文（寄存器）。
- 中断处理完后，通过 PendSV 中断恢复现场，切换到被中断的任务或更高优先级任务。

### 25. FreeRTOS 任务通讯方式（重要）

同第 8 点，核心为消息队列、信号量、互斥量、事件组、任务通知。

### 26. 互斥量与信号量的区别

- **信号量**：用于资源计数或事件同步（如计数信号量限制并发访问数），无优先级继承。
- **互斥量**：专为解决资源独占问题，支持优先级继承（避免优先级反转），只能由获取它的任务释放。

### 27. 互斥量解决优先级反转的原因

互斥量支持**优先级继承机制**：当低优先级任务持有互斥量时，若高优先级任务请求该互斥量，低优先级任务会临时提升至高优先级，避免被中等优先级任务抢占，从而减少高优先级任务的等待时间。

### 28. FreeRTOS 抢占式调度场景

- 高优先级任务就绪时（如外部中断触发任务唤醒），立即抢占低优先级任务。
- 中断服务程序中唤醒高优先级任务，中断退出后高优先级任务抢占执行。

### 29. 任务优先级设置

项目中任务优先级多设为 3（根据实际场景调整，确保核心任务（如数据采集）优先级高于非核心任务（如日志打印））。

### 30. MQTT 使用

使用过 EMQX 和 Mosquitto 等第三方 MQTT broker（服务器），实现设备与云端的消息通信。

### 31. MQTT 传输数据

主要传输业务数据，载荷为 JSON 字符串（如设备状态、传感器数据、控制指令等）。

### 32. MQTT 传输效率优化

- 选择合适 QoS 级别（如非关键数据用 QoS 0，减少开销）；
- 批量发送数据，减少报文数量；
- 压缩 JSON payload，降低数据量；
- 复用连接（避免频繁断开重连）。

### 33. MQTT 报文格式

- **固定报头**：包含报文类型（4 位）、标志（4 位）、剩余长度（1~4 字节）。
- **可变报头**：因报文类型而异（如 CONNECT 包含协议名、版本号）。
- **有效载荷**：数据内容（如 PUBLISH 的消息体），取决于报文类型。

### 34. MQTT 消息质量（QoS）

- **QoS 0**：最多一次，无确认，开销最小（如实时性要求低的传感器数据）。
- **QoS 1**：至少一次，有 PUBACK 确认，确保消息到达（默认推荐，如控制指令）。
- **QoS 2**：仅一次，通过 PUBREC/PUBREL/PUBCOMP 三次握手，确保消息唯一送达（高可靠场景，如金融数据）。

### 35. 项目升级方式

- **单片机**：通过 OTA（Over-The-Air）升级，从云端下载固件包，校验后更新。
- **QT 程序**：通过独立升级程序，下载新版本包，执行安装脚本替换旧程序。

### 36. 功能测试方式

根据测试人员编写的测试用例进行功能验证，包括正常场景、异常场景（如断网、数据异常），结合调试工具（如串口打印、日志分析）定位问题。

### 37. 低功耗设计

基于 STM32 配置低功耗模式（如 STOP 模式、STANDBY 模式），关闭闲置外设时钟，使用 RTOS 的 Tickless 模式减少系统滴答唤醒，优化 GPIO 状态（避免浮空耗电）。

### 38. 主板控制路数与传感器

- **控制**：通过电磁继电器芯片控制多路（8 路、12 路等）设备，支持 12V/24V 等电压。
- **传感器**：温湿度（DHT，单总线）、光照（ADC）、烟雾（ADC）、水滴（GPIO）。

### 39. 传感器数据传输

- 数字传感器（如 DHT）通过单总线传输数据；
- 模拟传感器（如光照、烟雾）通过 ADC 转换为数字量后读取；
- 数据经 MCU 处理后，通过 UART、WiFi 或 MQTT 发送。

### 40. 控制端发送信号

发送继电器开关指令（如高低电平信号）、电机控制信号（PWM 调速）等，通过串口或无线协议（WiFi / 蓝牙）传输。

### 41. 电机使用

用过伺服电机，用于控制窗帘等设备的精准运动（如角度控制）。

伺服电机是一种**闭环控制的高精度执行电机**，核心是通过 “位置 / 速度反馈 + PID 调节” 实现精准的运动控制（角度、速度、扭矩可精确管控），本质是 “指令信号→反馈信号→误差修正” 的闭环循环系统，主要由三部分组成：

1. **电机本体**：多为永磁同步电机（小功率场景主流）或直流有刷 / 无刷电机，提供动力输出；
2. **反馈装置**：核心部件（如编码器、旋转变压器），实时检测电机转子的位置、速度信息，并将数据回传给控制器；
3. **驱动器 / 控制器**：接收外部控制指令（如脉冲信号、模拟量信号），对比反馈信号与指令信号的误差，通过 PID 算法调整输出电流 / 电压，驱动电机修正运动偏差，直到误差缩小到允许范围。

### 42. 心跳机制

- 心跳频率：5 秒一次，通过 MQTT 协议传输。
- 数据内容：设备 SN（唯一标识）、时间戳（同步时间）、设备在线状态等。

### 43 说以pid算法

```tex
一、核心原理
PID 是闭环控制的经典算法，通过比例（P）、积分（I）、微分（D） 三个环节协同，依据 “目标值与实际值的偏差” 动态调整控制量，使偏差趋近于 0，实现精准稳定控制。
比例（P）：按当前偏差大小输出控制量，快速响应偏差（如温度偏低则加大加热功率），但单独使用存在稳态误差；
积分（I）：对偏差累积求和，消除稳态误差（如持续偏差时，累积量推动控制量直至偏差为 0）；
微分（D）：根据偏差变化率预测趋势，提前调整控制量，抑制超调与震荡（如温度快速接近目标时，提前减小功率）。
三者加权求和得到控制量，通过调试参数（Kp、Ki、Kd）平衡响应速度、稳定性与控制精度。
二、使用场景
核心适用于 “需将物理量精准稳定在目标值，且存在外部干扰 / 负载波动” 的场景，覆盖多领域：
工业控制：温度（窑炉、注塑机）、压力（锅炉、管道）、流量（化工输送）、液位（储罐、反应釜）的稳定控制；
运动控制：伺服 / 步进电机定位（机械臂、3D 打印机）、电机调速（传送带、风机）、舵机姿态控制（无人机、智能小车）；
嵌入式 / 物联网：智能家居（空调、窗帘、加湿器）、电池充电管理、平衡车姿态校准；
汽车 / 医疗：发动机怠速控制、呼吸机压力调节、输液泵流速精准控制等。
```
