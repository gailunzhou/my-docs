# 定时器编码器接口学习笔记

Date: 2025/12/30

定时器编码器接口模式一般用于编码器测速场景

测速的方式有很多，但以定时器编码器接口方式为主，该方式**对CPU占用较少**<br>
另一种方式是使用外部中断的方式进行测速，即通过外部中断获取对应引脚脉冲是增加还是减少，但该方法**对CPU占用较多，特别是高速情况下中断较为频繁**

## 1. 配置流程

一般的配置流程如下：

1. 开启RCC对应的定时器和GPIO的时钟
2. 配置GPIO，编码器接口模式下，需要**将IO配置为上拉输入模式**
3. 配置定时器时基单元 TIM_TimeBase
4. 配置定时器输入捕获单元 TIM_IC，编码器接口模式下，**只有输入捕获通道和滤波器两个参数有意义**
5. 配置编码器接口 TIM_EncoderInterfaceConfig
6. TIM_Cmd 开启定时器

!!! note "笔记1"
    - 在配置流程中，为什么没有`TIM_InternalClockConfig`?
    - 该函数是显示将内部时钟作为定时器时钟，而定时器默认情况下就是内部时钟，因此该函数其实只有在需要从外部时钟转为内部时钟设置时才需要用到
	- 使用编码器接口模式情况下，时钟是由外部脉冲进行提供

!!! note "笔记2"
    - GPIO的配置中，为什么是上拉输入IPU而不能是下拉输入IPD?
    - 首先上拉输入情况下，IO会被内部电阻拉高，默认情况下电平是高电平，同样下拉输入情况下IO默认是低电平<br>那么对应产生变换的电平分别就是IPU--低电平为有效电平，IPD--高电平为有效电平
    - 而编码器接口模式下，IO连接是对应编码器或者驱动的输出IO，而大部分厂商给编码器的输出都设置的是**空闲状态下高电平，有效电平为低电平**，因此和IPU模式是对应的，所以一般都选择IPU而不选择IPD

!!! note "笔记3"
    - 在编码器接口模式下为什么时基单元的ARR要设置为最大而PSC最好设置为0?
    - ARR最大：编码器接口模式下，**时钟的工作是对外部的脉冲进行计数**，从而进行测速等操作，因此如果想要测速精度够高，那么计数需要尽可能大，最好不丢失脉冲，而16位的寄存器最大就是65536，因此ARR需要设置为最大
    - PSC设置为0：编码器接口模式下，时钟的工作是对外部的脉冲进行计数，而**此时的PSC（预分频器）就会对获得的脉冲进行分频**，即假如设置为2分频，那么计两次脉冲才会记一次数，但是对于测速这样的场景，需要尽可能每一个脉冲都记上，所以最好是不分频

!!! note "笔记4"
    - 解释一下滤波器参数的含义：
    - TIM_ICFliter参数，滤波器会按照 **[定时器时钟]/2 为采样频率**，按照给定的参数作为采样次数，对输入捕获的信号进行采样滤波，该参数取值只能为0x0 --- 0xF (0 --- 15)
    - 举例：
    - `TIM_ICFliter = 0xF;`，假设这里的TIM使用的是TIM3，TIM3属于APB1总线，APB1总线的时钟是36Mhz，但APB1的分频系数是2，这里有这样的规则：
    - **如果APB分频系数>1，那么定时器时钟频率 = 所在总线时钟频率*2**
    - 因此定时器时钟为 36Mhz * 2 = 72Mhz，所以采样频率为 72Mhz / 2 = 36Mhz，而给的参数是0xF也就是要连续进行16次采样(0到15，共16次)，只有这16次采样的结果都相同，才认定为有效数据

!!! note "笔记5"
    编码器接口的配置函数`TIM_EncoderInterfaceConfig()`该函数中对两个通道极性的配置是**会覆盖之前输入捕获中TIM_ICPolarity的配置**
